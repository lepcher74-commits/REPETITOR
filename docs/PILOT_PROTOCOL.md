# Controlled pilot protocol

Stage: 8 / E8.8
Status: protocol baseline; real-user launch remains gated.

## Purpose

Evaluate whether the pilot build is operationally safe, understandable and capable of producing interpretable learning evidence in the grade-6 fractions slice. This pilot is not designed to establish broad product efficacy.

## Participants and authorization

Before enrollment, the pilot operator must define:
- jurisdiction and operator/controller role;
- participant age range and inclusion/exclusion criteria;
- guardian/consent or other authorization workflow required for that setting;
- support contact and withdrawal/deletion procedure.

No participant is enrolled until those items are recorded.

## Session scope

[ДОПУЩЕНИЕ] Initial operational protocol:
- 3–5 learning sessions per participant;
- approximately 20–30 minutes per session, with breaks available at any time;
- use only the approved grade-6 fractions pilot content;
- no production network AI provider unless separately reviewed and approved.

These durations are operational defaults, not claims about optimal learning dosage.

## Measures defined before observation

Primary product/pedagogical evidence:
- diagnostic-to-later independent correctness on the same skill class using different authored problems;
- change in mastery dimensions generated by the pre-existing deterministic learning engine;
- independent vs hinted evidence count;
- transfer-task correctness;
- delayed review correctness when a review becomes due.

Operational/safety evidence:
- startup/recovery failures;
- lost or inconsistent local state;
- exhausted evidence pools;
- accessibility blockers;
- participant/support reports of confusing or unsafe behavior.

Do not use time-in-app, streaks or repeated clicks as success metrics.

## Data minimization

The default pilot uses the existing local SQLite evidence model. Export/central collection is not authorized by this protocol. If aggregated research or support export is later required, its fields, purpose, transfer mechanism, retention and authorization must be approved before collection.

Free-text learner answers must not be added to startup diagnostic logs.

## Incident procedure

Stop the affected participant session and preserve the local data directory if any of the following occurs:
- suspected data loss or incorrect learner-state overwrite;
- application repeatedly crashes or cannot safely open the learner database;
- content presents a material safety/age-appropriateness issue;
- scoring is demonstrably wrong for a supported formal-verification task;
- accessibility prevents the intended participant from operating the required flow.

Record reproduction steps without copying unnecessary child data into issue text.

## Pilot stop conditions

Pause enrollment if:
1. a critical data-loss defect is confirmed;
2. formal scoring can silently mark an incorrect supported answer correct;
3. a required child-safety/privacy gate is unmet;
4. a known accessibility blocker affects the intended pilot population;
5. the content/evidence pool is insufficient to interpret progression without recycling identical evidence.

## Interpretation

This is a small controlled product pilot, not a randomized efficacy trial. Pre/post changes may reflect practice, selection, maturation, task familiarity or other confounding factors. Report descriptive results and uncertainty; do not claim causal learning efficacy or generalize beyond the observed pilot population/content.

## Exit evidence for Stage 8

Before the Controller pilot-readiness gate:
- PR-01–PR-14 status is recorded against a final candidate commit;
- intended pilot environment manual accessibility results are attached;
- privacy/child-safety manual checklist items required for that environment are resolved;
- final CI and pilot-build matrix are green;
- residual risks and all NOT TESTED items are explicit.
